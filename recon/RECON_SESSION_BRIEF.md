# Инструкция разведывательной сессии

Вы — разведывательная сессия Claude на ноутбуке, подключённом к стендовому пульту VCM. Ваша задача — **собрать факты** о подключённом ЭБУ по плану `recon/README.md` и положить их в репозиторий. Решения принимает главная сессия; вы их не предлагаете.

## Жёсткие правила

1. Пишете только в `recon/logs/<ГГГГ-ММ-ДД>_<ecu-id>/` и одну строку в `recon/INDEX.md`. Ничего другого в репозитории не трогаете: ни `*.ino`, ни `README.md`, ни `tools/`, ни `recon/README.md`, ни `recon/DECISIONS.md`.
2. Прошивку не меняете. Если пульт надо прошить — прошиваете файл `VCM_Iveco_TSC1_75.ino` из репозитория как есть (`DEBUG_LEVEL 2`). Сборка: скопировать файл в `build/VCM_Iveco_TSC1_75/` и `arduino-cli compile --fqbn arduino:avr:nano --upload -p <порт> build/VCM_Iveco_TSC1_75` (библиотеки `autowp-mcp2515`, `LiquidCrystal I2C`), либо Arduino IDE.
3. Команды пульту отправляете только из списка плана: `h`, `e`, `s`, `i`, `q <PGN>`, `p N` (только по правилу шага A6), `/mark`, `/ident`. Команды `a`, `m` — только если оператор прямо просит записать отклонение по разд. 5 плана, и это фиксируется в отчёте.
4. Ничего физически не делаете: ключ, стартёр, педаль, кнопки пульта — оператор. Вы просите оператора выполнить шаг и ставите `/mark`.
5. В отчёте — только то, что видно в логе и на экране, плюс отклонения и вопросы. Слова «предлагаю», «нужно изменить», «рекомендую» в отчёте не используются.
6. Коммит после каждого ЭБУ: `git add recon/ && git commit -m "recon: <ecu-id> — <статус одной строкой>" && git push origin claude/determined-gates-a7k9ez`. Перед началом работы `git pull`.

## Порядок работы

1. `git checkout claude/determined-gates-a7k9ez && git pull`.
2. Спросить оператора: модель двигателя, наклейка ЭБУ, стенд/машина, номер экземпляра → составить `<ecu-id>` по разд. 3 плана.
3. Убедиться, что установлен Python 3 и `pyserial` (`pip install pyserial`). Найти порт: `python recon/tools/recon_capture.py --list`.
4. Запустить запись: `python recon/tools/recon_capture.py --port <порт> --ecu <ecu-id>`. Проверить баннер `VCM READY. FW 75`. Если версия другая — остановиться и сообщить оператору.
5. Пройти фазу A (шаги A1–A8) и фазу B (B1–B9) из `recon/README.md`, перед каждым действием оператора ставить `/mark <что делаем>`. Отвечать оператору коротко, что ожидается увидеть в логе и появилось ли это.
6. `/quit`. Открыть `report.md`, заполнить все разделы шаблона. Проверить `summary.md`: если автосводка противоречит логу, в отчёте указать это как факт.
7. Добавить строку в `recon/INDEX.md`, закоммитить, отправить.
8. Для следующего ЭБУ — с шага 2. Если в этот день уже был другой ЭБУ, выполнить шаг B9 (проверка автопереключения).

## Если непонятно, что делать

Записать ситуацию в `report.md`, раздел «Вопросы к главной сессии», отметить в `/mark`, остановиться на этом шаге и продолжить следующие шаги, которые не зависят от него. Не импровизировать с адресами, настройками и прошивкой.
