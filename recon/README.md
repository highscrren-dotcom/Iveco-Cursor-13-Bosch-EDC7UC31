# План разведки ЭБУ (FW 75)

Разведка отвечает на вопрос «как ведёт себя конкретный ЭБУ с пультом», ничего не меняя в прошивке. Её результат — логи и отчёты в `recon/logs/`, по которым главная сессия принимает решения (`recon/DECISIONS.md`).

## 0. Роли и правила

- **Главная сессия** — решения: прошивка, документация, разбор логов. Только она меняет файлы вне `recon/` и пишет в `recon/DECISIONS.md`.
- **Разведывательная сессия** — сбор фактов по этому плану. Пишет только в `recon/logs/<дата>_<ecu-id>/` и добавляет строку в `recon/INDEX.md`. Инструкция для неё — `recon/RECON_SESSION_BRIEF.md`.
- Разведка **не делает**: правки `*.ino`, `README.md`, сборочных флагов (`DEBUG_LEVEL` остаётся 2), сброс настроек пульта, подбор адресов сверх штатного автоподбора, выводы и рекомендации. Если протокол не покрывает ситуацию — зафиксировать факт, задать вопрос в отчёте, остановиться.
- Ветка `main`. Перед началом `git pull`, коммит после каждого ЭБУ, сообщение `recon: <ecu-id> — <статус одной строкой>`.
- Всё, что собрано, обозначено: папка с датой и идентификатором ЭБУ, внутри `serial.log` (сырой лог), `summary.md`/`summary.json` (автосводка скриптом), `report.md` (отчёт по шаблону), при наличии `photos/`.

## 1. На какие вопросы отвечает разведка

| № | Вопрос | Где ответ в логе |
| --- | --- | --- |
| 1 | Отвечает ли ЭБУ на запросы идентификации: Component ID (65259), Software ID (65242), Address Claim (60928)? Что именно? | `ID src0/1/2 @…`, `NACK … pgn=`, `ID done src=… name=…`, вывод `q FEEB` / `q FEDA` / `q EE00` |
| 2 | Стабилен ли отпечаток (`fp`) между включениями зажигания и между включениями питания пульта? | два и более `ID done … fp=0x…` для одного ЭБУ |
| 3 | Различаются ли отпечатки у разных экземпляров одного типа ЭБУ? Где в тексте серийный номер, где модель/датасет? | сравнение `ID src…` текстов разных ЭБУ |
| 4 | Заполняет ли ЭБУ SPN 1483 (адрес управляющего устройства)? | `ctrl=` в heartbeat при нажатой педали, `*` на экране, `SA FOUND … (SPN1483)` |
| 5 | Какой адрес источника слушает ЭБУ? Сработал ли автоподбор, по какому критерию, за сколько шагов? | `SWEEP next SA=`, `>>> SA FOUND 0x.. (SPN1483\|rpm)`, `SA saved` |
| 6 | Отвечает ли ЭБУ на глобальный запрос DM2? Как приходит DM1: одиночный кадр или BAM? | `DM2 1-frame` / `BAM start pgn=65227`, `>>> DTC:` |
| 7 | Какие PGN ЭБУ вещает (живые данные)? | `PGN seen …` в начале лога, страницы данных на экране |
| 8 | Есть ли аномалии: сбои отправки, переинициализации CAN, перезагрузки пульта, нехватка памяти? | `TSC1 TX FAIL`, `CAN re-init`, повторный `=== START VCM`, `ram=` в heartbeat |
| 9 | Работает ли управление оборотами и как ведёт себя ЭБУ на холодную и на горячую? | `set=`/`act=`/`T=` в heartbeat, `ENGINE STOP->RUN` |

## 2. Оборудование и подготовка

- Пульт с FW 75 (при включении на экране `FW 75  CAN: OK`, в логе `VCM READY. FW 75`). Прошивать **неизменённый** файл из репозитория, `DEBUG_LEVEL 2` по умолчанию.
- Ноутбук с USB-кабелем, Python 3 и `pyserial` (`pip install pyserial`). Запись лога ведёт `recon/tools/recon_capture.py`. Если Python недоступен — любой терминал с записью в файл (PuTTY, CoolTerm, Serial Monitor) и потом `recon_capture.py --summarize <файл>`.
- Гальваническая развязка USB (см. README разд. 5) — прокрутка стартёра с подключённым ноутбуком без развязки опасна для портов.
- Аварийный стоп и заслонка впуска на месте, оператор у двигателя. Разведывательная сессия работает только с ноутбуком и не трогает педаль и ключ.
- Данные об объекте: модель двигателя, наклейка ЭБУ (производитель, номер Bosch `0 281 020 xxx`, заказной номер, номер ПО), машина или стенд. Можно сфотографировать: `photos/` в папке лога (сжато, до ~500 КБ на фото).

## 3. Идентификатор ЭБУ и папка

`<ecu-id>` = `<двигатель>-<эбу>-<nn>`, строчные латинские буквы и дефисы: `iveco-cursor13-edc7-01`, `kamaz-740-edc7-01`, `kamaz-cummins-cm2150-01`. Номер `nn` различает экземпляры. Папка: `recon/logs/<ГГГГ-ММ-ДД>_<ecu-id>/`. Тот же экземпляр в другой день — новая папка с новой датой, тот же `ecu-id`.

Запуск записи (порт смотреть `python recon/tools/recon_capture.py --list`):

```sh
python recon/tools/recon_capture.py --port COM5 --ecu kamaz-740-edc7-01
```

Скрипт пишет `serial.log` с метками времени, принимает команды для пульта (`e`, `i`, `q FEEB` …), пометки оператора `/mark <текст>`, макрос `/ident`, а по `/quit` создаёт `summary.md`, `summary.json` и заготовку `report.md`.

## 4. Процедура для одного ЭБУ

Каждое действие оператора отмечать в логе командой `/mark`, чтобы потом было видно, что происходило в этот момент.

### Фаза A — зажигание включено, двигатель не заводим

| Шаг | Действие | Что должно появиться в логе | Что записать |
| --- | --- | --- | --- |
| A1 | Подключить пульт к шине и к ноутбуку, запустить скрипт записи. Открытие порта перезагружает Arduino — это нормально | баннер `VCM READY. FW 75`, `cfg …`, `EEPROM ok`, список пресетов | версию FW, активный пресет, уже привязанные `fp` |
| A2 | `/mark ignition on`, включить зажигание, ждать 15 с | `BUS alive -> ECU ID request scheduled`, `PGN seen …`, `ID request src0/1/2`, `ID src… @…: …` или `NACK … pgn=…`, `ID done src=… fp=0x… name='…' match=…` | таблицу ответов по трём источникам, `fp`, маркер на экране (`?`, `A`, пусто) |
| A3 | `/mark ignition off`, выключить зажигание, ждать 3 с (`BUS lost`), `/mark ignition on`, включить, ждать 15 с | второй `ID done` | совпал ли `fp` с A2 |
| A4 | `/mark device power cycle`: отключить USB пульта (питание), подключить снова, скрипт перезапустить если порт пропал; зажигание выключить и включить | баннер, пресеты из EEPROM, третий `ID done` | совпал ли `fp`, сохранились ли пресеты |
| A5 | Выполнить `/ident` (макрос: `e`, `i`, `q FEEB`, `q FEDA`, `q EE00`, `q FDC5`, `q FEEC`, `q FECB`, `e` с паузами). Если ЭБУ не ответил на `i`, повторить `/ident` ещё раз | строки `RECON pgn=… hex: … '…'`, `ACK/NACK … pgn=…` | что пришло по каждому PGN, какие NACK |
| A6 | Если на экране маркер `?` (ЭБУ неизвестен): привязать к пресету **по правилу**: Iveco → `p 1` (IVECO), КамАЗ с EDC7 → `p 2` (KAMAZ), любой другой ЭБУ → `p 3` (ECU-3). Если маркер `A` — ничего не делать | `PRESET -> … (manual, ECU fp=0x… privyazan)` | к какому пресету привязан |
| A7 | `/mark ignition off/on`: выключить и включить зажигание, ждать 15 с | `ID done … match=<пресет>`, на экране `ECU opoznan`, маркер `A` | опознан ли автоматически |
| A8 | На экране: READ коротко 4 раза — записать 4 страницы данных (значения или `---`), ещё READ — экран ошибок, BACK | `>>> DTC: … kod(ov)`, `DM1 1-frame`/`BAM start pgn=65226`, `BAM start pgn=65227`/`DM2 1-frame` или ничего | коды, пришёл ли DM2 |

### Фаза B — с двигателем (оператор у двигателя, аварийный стоп под рукой)

| Шаг | Действие | Что должно появиться в логе | Что записать |
| --- | --- | --- | --- |
| B1 | `/mark engine start`, завести двигатель, прогревать. Пока греется, не трогать педаль и кнопки | `ENGINE STOP->RUN rpm=…`, `PHASE WAITRUN->SETTLE->RUN` (FIXED) или `->SCAN` (AUTO); heartbeat `act=`, `T=`, `ctrl=` | холостой, `ctrl=` на холостом, рост `T=` |
| B2 | Пресет в режиме **AUTO** (КамАЗ): наблюдать перебор. Обороты будут подниматься на 450 на каждом удачном шаге, это штатно | `idle ~… rpm. SWEEP start`, `SWEEP next SA=0x..`, `>>> SA FOUND 0x.. (SPN1483)` или `(rpm)` | список адресов, результат, критерий |
| B3 | Нашёл: на экране `SA 0x.. najden! / CLR=sohranit` — оператор нажимает **CLEAR** в течение 10 с (предписано планом). Не нашёл за полный круг по всем адресам (около 25 с после прогрева) — оператор нажимает **BACK**, поиск остановлен | `SA saved 0x..` / `SWEEP aborted by BACK` | сохранён ли адрес; «не найден» — факт, без догадок |
| B4 | На холодном двигателе (T ниже ~60 °C) `/mark pedal cold`: оператор плавно нажимает педаль до середины на 3 с и отпускает | `CMD speed target=…`, `set=` растёт, `act=` **не** растёт, `ctrl=` | игнорирует ли холодный ЭБУ команду |
| B5 | На прогретом (T не ниже 70 °C) `/mark pedal warm`: плавно до ~1000–1200 об/мин, держать 5 с, отпустить | `set=`/`act=` сходятся, `ctrl=0x<наш SA>`, на экране `*` после адреса | работает ли управление, заполнен ли SPN 1483, задержка отклика |
| B6 | Повторить B5 с полным нажатием на 5 с, если оператор считает безопасным (лимит прошивки 2200) | `act=` у `RPM_MAX` | достиг ли, рывки |
| B7 | На экране READ до списка ошибок: записать коды на работающем двигателе, BACK. **CLEAR (сброс кодов) не нажимать** — это решение владельца двигателя | `>>> DTC:` | коды |
| B8 | `/mark engine stop`, заглушить, ждать 5 с, выключить зажигание | `ENGINE RUN->STOP`, `BUS lost` | — |
| B9 | Проверка переключения: если в этот день уже разведан другой ЭБУ — подключить его снова и пройти A2 | `ECU opoznan`, маркер `A`, нужный пресет | переключился ли пульт сам |

### Фаза C — оформление

1. `/quit` в скрипте: появятся `summary.md`, `summary.json`, `report.md`.
2. Заполнить `report.md` по шаблону (`recon/TEMPLATE_report.md`): только факты из лога и экрана, отклонения от процедуры, вопросы. Без рекомендаций.
3. Добавить строку в `recon/INDEX.md`.
4. `git add recon/ && git commit -m "recon: <ecu-id> — <статус>" && git push`.

## 5. Безопасность при шагах с двигателем

- Шаги B выполняет оператор у двигателя. Сессия на ноутбуке только пишет лог и команды `e`, `i`, `q …`, `s`, `h`. Команды `p`, `a`, `m` во время работы двигателя пульт отвергает (`refused: engine running`) — это правильно.
- Перед B1 оператор подтверждает: аварийный стоп и перекрытие впуска под рукой, педаль пульта в нуле.
- Любая ненормальность (рывки, нестабильные обороты, дым, запахи, перезагрузка пульта) — заглушить, записать `/mark abort <причина>`, продолжать нельзя.
- Автоподбор поднимает обороты. Если оператору это нежелательно, перед пуском перевести пресет в FIXED командой `m` (при остановленном двигателе) и записать это как отклонение от процедуры.

## 6. Если что-то идёт не так

| Ситуация | Что делать разведке |
| --- | --- |
| После включения зажигания нет `BUS alive`, `bus=0` в heartbeat | Записать факт. Проверить разъём CAN-H/CAN-L и питание, одна повторная попытка. Не менять скорость шины и прошивку. Вопрос в отчёт |
| `ID: net otveta ECU`, маркер пустой | Нормальный исход для части ЭБУ. Выполнить `/ident` дважды, записать все `NACK`. Привязка невозможна — пресет выбрать вручную по правилу A6 (длинный READ или `p N`), это зафиксировать |
| `fp` в A2 и A3 не совпали | Записать оба, повторить A3 ещё два раза. Приложить полный лог. Не привязывать |
| Поиск адреса не нашёл ничего | BACK, записать пройденные адреса. Не пробовать свои адреса |
| На экране `EEPROM: defaults` при включении | Записать. Если повторяется при каждом включении — вопрос в отчёт |
| Пульт перезагружается (повторные баннеры) | Записать когда (прокрутка стартёра? педаль?). Прекратить шаги B |
| Скрипт не видит порт | `--list`, проверить драйвер CH340/FT232. Запасной вариант — терминал с записью в файл, потом `--summarize` |

## 7. Когда разведка одного ЭБУ закончена

- В папке есть `serial.log`, `summary.md`, `summary.json`, заполненный `report.md`.
- Пройдены A1–A8; B1–B8 пройдены или в отчёте написано, почему нет.
- Есть минимум два `ID done` для сравнения отпечатков (или зафиксировано, что ЭБУ не отвечает).
- Строка в `INDEX.md`, коммит отправлен.

## 8. Что делает главная сессия с результатами

Сравнивает отпечатки и тексты идентификации между ЭБУ, решает правило отпечатка (весь ответ или только поля модели/датасета), пополняет `SWEEP_ADDRS` и словарь SPN, при необходимости правит тайминги опознания, меняет прошивку и документацию, записывает решение и ссылку на лог в `recon/DECISIONS.md`.
